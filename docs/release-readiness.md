# Release readiness gate

This checklist is intentionally conservative. Passing engineering CI does not by itself mean a public package or commercial launch is legally, operationally, or security-ready.

## Current release state

- [x] **Legacy VibeTrace brand retired from new product/package/CLI surfaces.** Earlier exact and near-exact software uses made the old name unsuitable for continued investment.
- [x] **PatchOath engineering collision scan completed.** Exact-name searches across public developer/software/package contexts did not surface a material same-name conflict during the v0.3 migration review. See [`brand-clearance.md`](brand-clearance.md).
- [ ] **Formal commercial trademark clearance completed for target jurisdictions/classes.** Public searches reduce obvious collision risk but are not a legal opinion or registration clearance.
- [x] npm package remains `private: true` during the v0.3 migration, final CI, repository-slug migration, and explicit public-release decision.
- [ ] Repository slug, package-publication plan, release notes, and external links are migrated as one coordinated release action.

## Rights and provenance

- [x] Repository source is licensed under MIT.
- [x] Current npm dependency licenses are recorded in [`THIRD_PARTY_NOTICES.md`](../THIRD_PARTY_NOTICES.md).
- [x] Current project visual assets are recorded in [`asset-provenance.md`](asset-provenance.md).
- [x] The PatchOath vector mark is project-authored and stored in-repository.
- [x] Current repository-controlled source, documentation, and first-party visual assets have an explicit provenance/rights baseline enforced by `npm run rights:check`; newly introduced third-party material remains a review event.
- [ ] If outside contributions are accepted at scale, decide whether to require DCO sign-off or another contribution provenance mechanism.

## Product and claim review

- [x] Current repository-controlled README, Dashboard, package metadata, legal documentation, and tested CLI surfaces use the same conservative capability boundaries as the implementation.
- [x] Repository claims do not say or imply that PatchOath invented prompt tracking, AI diff tracking, blast-radius analysis, risk scoring, change authorization, policy repair, evidence receipts, session replay, review records, or selective disclosure as general concepts.
- [x] Current originality language is limited to the project's specific composition, semantics, implementation, and tested invariants rather than broad abstract ideas.
- [x] Third-party products are named only where needed for prior-art/related-work or ecosystem context; current first-party product surfaces do not embed third-party product logos.
- [x] Security/risk output is explicitly documented as a deterministic review heuristic/integrity signal rather than a guarantee of safety, legal compliance, non-infringement, authorship, reviewer identity, or semantic correctness.
- [ ] Re-review any future launch posts, release notes, website copy, ads, screenshots, and badges at publication time; repository review does not pre-approve future marketing copy.

## Migration and compatibility review

- [x] Fresh repositories create `.patchoath/`, `refs/patchoath/`, and PatchOath evidence-ID namespaces.
- [x] Existing `.vibetrace/`, `refs/vibetrace/`, and v0.2 evidence IDs remain compatible without silent historical-evidence rewriting.
- [x] The deprecated `vibetrace` CLI shim emits a migration warning while the primary `patchoath` path creates modern namespaces.
- [x] Standalone reports generated by v0.3 use PatchOath branding while report readers retain legacy-evidence compatibility.
- [x] Dedicated compatibility tests cover fresh PatchOath evidence and deliberately constructed legacy evidence paths.

## Package and dependency review

- [x] Distribution allowlist excludes `node_modules`, tests, CI files, and development scripts.
- [x] Release package includes `LICENSE`, `LEGAL.md`, and `THIRD_PARTY_NOTICES.md`.
- [x] Packaged CLI smoke tests pass on both Ubuntu and Windows for the current private-package baseline.
- [ ] Any new runtime/optional dependency has a deliberate packaging model and license review.
- [ ] Optional Playwright/PNG tooling has an install path that works for the intended public release channel without implying that browser binaries are PatchOath-authored or MIT-licensed.
- [ ] Public package name availability is checked again immediately before publication; the current private package state does not reserve a registry name.

## Privacy and security review

- [x] Current local evidence/disclosure behavior is aligned across [`LEGAL.md`](../LEGAL.md), [`SECURITY.md`](../SECURITY.md), the README, and disclosure-boundary documentation.
- [x] Minimum-disclosure Capsule defaults are covered by tests and remain narrower than the full local report.
- [x] Historical Effect Review is regression-tested as retrospective only and cannot mutate the source Change Contract or grant future execution authority.
- [x] Dashboard review surfaces remain read-only for historical review records and distinguish full local evidence from a share-oriented Capsule.
- [ ] Any future telemetry, cloud sync, accounts, payments, hosted reports, or retention policy is reviewed before implementation claims or launch.
- [x] Security guidance explicitly warns against publishing private repository contents, credentials, prompts, source paths, screenshots, or other sensitive evidence in public issues.

## Validation baseline

The merged v0.3 baseline has passed, both on the migration pull request and again on the resulting `main` commit:

- [x] Node 20 core checks, `rights:check`, and unit/integration tests.
- [x] Node 22 core checks, `rights:check`, and unit/integration tests.
- [x] Chromium E2E, including desktop review flow and 390 px mobile overflow checks.
- [x] Ubuntu packaged CLI smoke.
- [x] Windows packaged CLI smoke.
- [x] Formatting checks.

A green baseline is evidence for the tested invariants only; it is not a security certification or legal clearance.

- [ ] `main` requires pull requests and successful CI/status checks before merge.
- [ ] Required checks include both Node versions, browser E2E, Ubuntu/Windows package smoke, formatting, and `rights:check` through their current workflow jobs.
- [ ] Administrative bypass policy is reviewed deliberately rather than assumed safe because CI exists.

## Commercialization review

Before a paid US/EU or multi-jurisdiction launch, obtain appropriate professional review for the intended name/mark, business model, privacy obligations, and—where material—patent/freedom-to-operate questions. Public prior-art and name searches are useful engineering diligence but are not substitutes for jurisdiction-specific legal analysis.

A checked box records a repository fact at the time it was reviewed; it is not a permanent legal conclusion. Re-run the review when dependencies, assets, distribution model, product name, data flow, target jurisdictions, or commercial scope changes.
